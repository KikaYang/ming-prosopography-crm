## Generation of the evaluation tables (from 2026-11-03; approved by the author)

- The evaluation tables for SL12, SL11 and SL14 are generated by `scripts/eval/sl12.py`, `sl11.py` and `sl14.py`, which reproduce the tables in data/evaluation/ byte for byte (checked by `tests/test_eval_tables.py`).
- Each script = a base (BASE: the first-pass judgements at the case's v1 tag, first-pass judgement by AI agent (Claude Code), transcribed once and not changed afterwards) + an override table (OVERRIDES: every later change, applied in order, each with date, author and round). The changes of v1.1 / v1.2 were written into OVERRIDES from the differences between the version tags.
- Every future change of judgement is made in the script's OVERRIDES, and the table is then rewritten by running the script; the tables are not edited directly.
- Evidence is checked at run time: model evidence by looking up the triples in the ttl + vocab files at the version recorded in EVALUATED (copied in `evaluated_versions/`); CBDB evidence by SQL (skipped if the database is not present).
- Base for SL12: cbdb and event from eval-v1 (044c9bc), state from eval-state-v1 (420d9d4). The earlier trial evaluations (c1e28eb, b691c88) have no cause column and are not used as base. Overrides are entered commit by commit; untagged commits between tags (1f6edbd, 1dfe23d, 3423040) are listed separately so as to keep their own dates and reviewers. When SL12 was brought into this scheme (2026-11-04), the tables did not change and the evaluation results are the same.

## Competency questions

`competency_questions.csv` contains competency questions v1.0 (written and approved by the author, 2026-11-04; tag cq-v1). Columns: `cq_id, question, gold_answer, basis, tests, review_note` (UTF-8, CRLF line endings; line breaks within cells are kept as LF, as in the original worksheet).

- The questions and gold-standard answers were frozen before the queries: cq-v1 was tagged before any query was written, and is not changed in response to query results; any change requires a new version with the reason stated.
- The gold-standard answers are based on the historical sources, not on the models.
- A correct answer may be "unknown".
- An answer counts as correct only if it presents a divergence as a divergence; giving only one of the competing statements does not count.

## Rule for vocab.ttl (approved by the author, 2026-11-02)

vocab.ttl only grows and is never reduced; after moving or adding vocabulary, the graph of each case file merged with vocab must be a superset of its earlier graph (all earlier triples kept unchanged), checked by script.

- Script (in the author's development repository; not included in this snapshot, since the check needs the commit history): `python scripts/check_vocab_superset.py` (by default compares HEAD with the working tree; `--base`/`--target` compare any two versions; `--history vocab-rule-start` checks each later commit that changed vocab.ttl).
- Test: `tests/test_vocab_superset.py` checks the whole history from the tag vocab-rule-start (the last commit changing vocab.ttl before the rule took effect), and also the working tree if vocab.ttl has uncommitted changes.
- First application: 015fb5f, moving shared persons into vocab (approved by the author, 2026-11-02). The merged graphs are strictly isomorphic only for case files that use all the moved vocabulary; for other files the only additions are vocabulary they do not use, which this rule accepts.
- The rule covers only moves and additions in vocab. Changes to the case files themselves (blocks written by Yang) are not restricted by it, but should not be placed in the same commit as changes to vocab, or the check will report a violation.
- Supplement (2026-11-12): English labels and English explanations may be revised, and revisions are recorded in the change log; structural triples still only grow and are never removed.

## Evaluation rules v1 (frozen on 2026-10-28)

All later cases are evaluated under the rules in this section. Any change requires a new version (v2, v3, …) with the reason stated; cases already evaluated are not re-judged retroactively.

### Objects and procedure

- Only units with `in_scope = 是` (yes) in the list are evaluated; units marked `否` (no) (and formerly "待核", to be checked) are not.
- Following D11: first list the information units, then model, then evaluate. SL12 is the exception (its list was drawn up after modelling, as a trial run of the method; see D11).
- For every unit judged as retained (kept / kept_ext / kept_judgement), evidence must be given: for the models, the corresponding triples, whose presence in the ttl files (including vocab.ttl) is checked by script; for CBDB, the posting_id or "table.field". For rows judged lost, the evidence column is left empty.
- Only triples count. Turtle comments (`# …`) are not triples and do not count as expression.

### Judgement values

| Value | Definition | Applies to |
|---|---|---|
| kept | There is a direct structured expression: structured fields in CBDB (office codes, years, alternative-name table, etc.); triples built from CRM properties in the model | CBDB, models |
| kept_ext | Expressed only by means of an extension property (`mpv:`) | models |
| kept_judgement | Expressed only through the modeller's judgement: e.g. an implicit subject written as the Shizong emperor, reading 台 as 召, inference under D5 (titles have no withdrawal events) or D12 (within a series a later title replaces an earlier one) | models |
| notes_only | Appears only in free text such as `c_notes`, which machines cannot query directly (R1) | CBDB |
| partial | Partly retained: e.g. a date only to the year; the title present but the *jian* relation lost; the original string not created but its component titles present; the information kept only in the text of the original title string (E41 label) (this item approved by the author, 2026-10-28) | CBDB, models |
| distorted | The form of representation leads to a wrong inference, e.g. after a title is replaced, old and new titles are inferred to be held at the same time; a mention in office recorded as the start of a tenure | CBDB, models |
| lost | Not found | CBDB, models |
| not_modelled | The content is outside the modelling scope (e.g. Yang Yiqing, the process of declining an appointment) | models |

Supplementary rules:

- Relation units (type = relation): only a structured link among the objects counts as kept. If the objects are independent but their coexistence can be inferred from year ranges, the unit is partial; if even that cannot be inferred, it is lost. The note states which case applies.
- Title replacement is inferred under D12 (within the same broader class, a later title replaces an earlier one), and the inferred result is judged kept_judgement; if a title needed for the inference is not modelled, the unit is judged partial / omission (precedent: J089-U23).
- Implicit units (those whose note in the list says "隐含", implicit) are judged as usual; in the output `implicit = 是` (yes), and they are counted separately.
- Units that cannot be judged are not forced into a judgement; the reason is written in the note and the matter is left to the reviewer. The v1 trial evaluation temporarily used `unclear`; all such cases were resolved during review, and the judgement values of this rule set do not include unclear. (approved by the author, 2026-10-28)

### cause (filled only for rows not judged as retained)

| Value | Definition |
|---|---|
| limit | The representation system itself cannot do it: for CBDB, its table structure; for the models, what CRM plus the decisions already taken (D1–D15) can express |
| omission | A means exists, but the information was not recorded or not modelled |
| scope | The content is outside the scope of recording or modelling in the first place |

- R1 (approved by the author, 2026-10-22): information that appears in free text such as c_notes is judged notes_only and does not count as structured retention; the cause is judged by whether the structure can express it.
- Retained judgements (kept / kept_ext / kept_judgement) have no cause.

### Information-unit list (info_units.csv)

Columns: `unit_id, type, text, about, links_to, in_scope, note` (UTF-8, CRLF line endings).

- `unit_id`: `J{three-digit juan number}-U{two-digit sequence number}`, e.g. `J089-U01`.
- Values of `type` (those occurring in v1.1): title, event, relation, issuer, title_string, name_form, date, action, source, motive, status, privilege, address, note.
- `in_scope`: 是 (yes) / 否 (no).
- From v1.2 onwards, links_to uses full identifiers separated by semicolons (e.g. `J118-U07;J118-U08`); rows of v1.1 and earlier keep their original form and are not changed retroactively.
- `note`: "隐含" (implicit) marks an implicit unit.

### Evaluation tables and summaries

- Columns of the evaluation tables: `unit_id, type, text, judgement, cause, <evidence>, implicit, note`; `<evidence>` is `cbdb_evidence` in the CBDB tables and `ttl_evidence` in the model tables (several triples separated by " ; ").
- Summaries are generated by `summarize.py`: one row per type, each judgement value written as x/n, followed by n_nonkept and each cause as x/n_nonkept; finally the rows "合计" (total) and "其中 implicit=是" (of which implicit). `summarize.py` also checks that the judgement values are valid and that the cause is filled in according to the rules.

## Reporting split: "caused by convention" within limit (2026-10-31)

This is a finer split in how results are reported, not a change to the judgement rules; the frozen rules v1 are unchanged, and the judgement values and causes are not affected.

- In the model evaluation tables (event and state versions of SL12 and SL11), rows with cause = limit that result from a convention set by this project (CRM could have expressed it, but a decision chose not to) have "约定所致（Dx）" (caused by convention Dx) added at the end of the note. `summarize.py` splits out a `cause_limit_convention` column after cause_limit (in the three-way tables, `*_limit_convention`).
- Marked as caused by convention (first-pass classification: AI agent (Claude Code); not yet approved): D4, no type for *jian*; D19, existing posts not created as events; D15, no events in the state version (including the resulting absence of occasion, issuer, action and grouping); D22, rejection of the "team" E74 and no assignment nodes in the state version.
- Not marked: the rows of the state version concerning "no time". CRM allows P4 only on an E2 Temporal Entity, and neither properties nor PC107 are E2; this is a limitation of CRM itself (rule 2 of D15 only decides not to add a further extension). SL11 state U46 has both kinds of cause and is marked "约定所致（D15、D22；‘照旧’的时间部分属 CRM 本身）" (caused by conventions D15 and D22; the time aspect of "as before" belongs to CRM itself).
- The CBDB tables do not use this split.

## Judging conventions for SL11 (approved by the author, 2026-10-31)

The following explain how rules v1 are applied; they are not changes to the rules.

1. Name units (name_form): judged kept only if the person has a separate name E41; judged partial if the name appears only in the original title string or in the person's rdfs:label (based on the definition of partial in rules v1 and the precedent of J136-U17, 孚敬). Cause: omission for the three core persons, scope for other persons under D21. (approved by the author, 2026-10-31)
2. Forms of address in the edict such as "卿某" (Minister so-and-so) in CBDB: if the person is present but the form of address is not recorded, partial / scope; if the original gives the full name, kept. (approved by the author, 2026-10-31)
3. The scope of limit is "CRM + all decisions in force at the time of modelling (in this case D1–D22)". D16–D22 belong to the model and are not changes to the evaluation rules. (approved by the author, 2026-10-31)
4. For blocks of a model not yet written, the units concerned are judged as they stand (cause = omission, noted in the note) and re-evaluated once the blocks are written. (approved by the author, 2026-10-31)
